# Nomo Scholar

打开 `.tex`、`.ltx` 或 `.typ` 稿件进入学术工作区。资源管理器目录内的稿件使用该目录作为项目根，其余稿件使用所在目录。首次进入时以当前稿件为主文件，文件树用“主文件”标记对应稿件。项目菜单可打开主文件，或将同项目的当前稿件设为主文件。

## 工作区布局

- **文档工具**保留布局菜单和检查器开关。新稿件默认使用“源码 + PDF”，同一标签保留布局、分栏比例和 PDF 阅读页。查找、引用和工作区命令从菜单栏或快捷键进入。
- **macOS 导航**在侧栏直接显示文件、文献、变更和大纲，项目文件树在下方显示。写作助手有独立入口。侧栏沿用 MyGo 的系统半透明材质。
- **Windows 导航**左侧应用栏的底部是账户与设置。账户页标明本地工作区，设置在主窗口打开。“文件”工作区承载项目树，宽窗口可收起，窄窗口选择文件后返回稿件。界面使用 Fluent 风格的布局和颜色。
- **PDF 区域**显示编译对应的文件名。暗色主题会调暗画布，纸页默认保留原色。月亮按钮可独立切换当前稿件标签的暗色阅读。点击页码可输入目标页，状态栏提供编译状态、页数和缩放。
- **检查器与写作助手**分别打开。文献详情和诊断使用检查器。宽窗口下写作助手可和源码、PDF 同时显示，窄窗口由“返回稿件”关闭助手并恢复原布局和页码。临时覆盖稿件时可保留已完成的 PDF，输入未变时直接恢复。

视觉布局参考了 Lattice 的项目导航、源码和 PDF 三区组织。Nomo 将各区的动作放进就近菜单，保留系统窗口控件与键盘入口。[Lattice 中文 README](https://github.com/leo1oel/lattice/blob/main/README.zh-CN.md)

默认主题是 `nomo-ios-blue`，浅色强调色为 `#0088FF`，深色为 `#0091FF`。用户选定的其他主题继续生效。文献、Codex 和 Diff 使用独立语义色。

## 引用与文献

### 项目书目与检索

主文件声明的 BibTeX、BibLaTeX、CSL-JSON 或 Hayagriva YAML 会建立项目索引。LaTeX 支持 `\bibliography{…}` 和 `\addbibresource{…}`，Typst 支持 `#bibliography("refs.yml")` 及字面量路径元组。宏生成的路径仍需改用可解析的声明。

在 LaTeX 输入 `\cite{`、`\parencite{` 或 `\autocite{`，或在 Typst 正文输入 `@`，会打开源码附近的检索浮层。可按标题、作者和引用键检索，使用 ↑／↓ 选择、Tab 勾选、Enter 连引、Esc 返回编辑器。Typst 数学、注释及 raw 区域由语法扫描排除。开启 Zotero 结果后，Alt+Enter 可导入当前条目并引用。菜单栏和快捷键也提供独立引用选择器。

引用浮层、文献列表和命令混搜按查询及索引实例缓存结果。磁盘索引查询在后台执行，改变查询会取消旧任务。悬停卡提供元数据、摘要片段、打开 PDF、精读、复制 BibTeX 和 Codex 上下文入口。原格式 BibTeX 的复制路径读取完整索引记录，保留原字段。项目导入保留实际导出记录及已有书目字节，校验重复键、DOI 和文件基准后原子替换。已打开的书目缓冲会阻止磁盘导入。

书目文件元数据每两秒在后台检查，变化后重建索引，打开的未保存缓冲优先。索引驻留预算为 8 MiB，包含首批不可变元数据、按字节淘汰的 LRU 和辅助结构。超出驻留预算时，完整元数据进入会话临时分桶索引，查询与引用校验覆盖全部条目。单个书目文件上限 512 MiB，单条记录上限 1 MiB，临时索引实际写入上限 128 MiB。打开的书目缓冲和一次原子导入有 64 MiB 合计读取预算，超出会明确报错。刷新、取消、关闭和过期发布均有释放路径。

### Zotero 与联网元数据

“文献”打开独立工作区。Nomo 自动探测 Zotero 本地接口，也可在文献工作区点“连接 Zotero”。需在 Zotero 的“设置 → 高级”允许本机其他应用通信。连接不可用时，项目书目与离线检索仍可用。文献库提供个人库、群组库、分类树、标签筛选、最近阅读、未分类条目、个人出版物和回收站。最近阅读记录当前项目会话打开过的附件。未分类条目逐页筛选，空页可继续翻页。

条目可以展开附件和子笔记。检查器显示条目元数据、子笔记文本、标签及关联条目。PDF 批注独立查看，并可跳到附件的实际页号。条目及标签列表按页加载，子分类展开时才读取。项目导入记录引用键与 Zotero 条目、群组和 DOI 的对应关系。

附件 PDF 在稿件标签栏打开，可固定并与稿件 PDF 或另一篇文献并排。窄窗口保留分栏选择，通过标签切换，每个标签记住自己的页码。阅读依赖本机 Poppler 的 `pdfinfo` 和 `pdftoppm`，也可从阅读器用 Zotero 打开。每项目会话最多 12 个附件标签，每份文件上限 128 MiB。只栅格化当前可见页，单页长边上限 1600 像素。离开阅读区时释放位图并取消尚未完成的加载。

Zotero 全文检索逐批扫描所选库或分类。扫描游标独立于结果分页，后续附件页也会读取。界面显示已扫描条目、总范围、可读 PDF 和无法读取／索引不完整的附件数量。每批最多 25 条元数据，点击“继续扫描”接续位置。结果累计至 200 条时明确提示，继续会替换这一批展示结果并保留扫描位置。缺少附件时仍保留标题、作者等元数据命中。取消或批次超时会保留已完成条目的结果，续查从尚未完成的条目重新读取附件。未索引的附件及响应大小或附件分页上限导致的不可用项单独计数。

离线全文检索同时检查元数据、摘要，以及书目 `file` 字段指向的项目内 PDF。PDF 文本通过本机 `pdftotext` 按需提取，未关联和无法读取的附件单独计数。扫描按每批 25 条续查，展示结果预算为 100 条，替换批次前有明确提示。单个 PDF 上限 128 MiB，提取文本上限 4 MiB，每份 PDF 超时为五秒。未配置附件的书目只能检索元数据和摘要。

DOI、arXiv 编号及论文标题可交给 Crossref／arXiv 检索。用户选择写入目标后才导入。相同 DOI 复用已有引用键，已有键冲突会阻止导入。Zotero 导出优先使用 Better BibTeX，群组及不可用情形走官方导出。批注引用保留页码，PDF 跳转使用实际附件页号。macOS 的附件 Quick Look 按钮可用 Space 激活，经 Zotero 本地文件 URL 接口取得路径后调用系统 `qlmanage -p`，项目取消会结束该进程。

[Zotero Local API](https://www.zotero.org/support/dev/web_api/v3/local_api) · [Zotero 官方本地接口定义](https://github.com/zotero/zotero/blob/main/_autodocs/endpoints.md) · [Better BibTeX JSON-RPC](https://retorque.re/zotero-better-bibtex/exporting/json-rpc/index.html)

## 本地编辑 Diff

Diff 基于编辑缓冲的前后快照。手动输入合批，撤销、重做与已接受 Codex 修改分别记录。待审提议和已应用记录分开显示，使用 `┆`／`│`、文字与 `+`／`−` 区分。

变更导航显示多处修改，可通过上一处／下一处、Alt+↑／↓ 和行号槽查看快览。短行复用 MyGo DiffView，长段落使用公开的文本背景 API，按单词、标点和 TeX 控制序列保留字节范围进行差异高亮。每侧 token 模型最多 8192 项，超过部分合并为尾部 token，原文换行与内容保持原样显示。

每个项目窗口保留最多 16 条、192 KiB 的差异片段，单侧片段上限 24 KiB。很长的改动显示截断提示。待处理共享快照使用 64 MiB 逻辑预算，过载时合并连续批次或明确提示较早批次被淘汰。此历史与编辑器 Undo 栈独立。最近一批适合预算的编辑保留前后共享快照，可执行编辑版本 PDF 对照，逻辑预算为 16 MiB。

## Codex 提议与跨文件审阅

写作助手在连接 Codex 后显示实际可用模型。输入 `/` 或点击斜杠菜单可以选用 Nomo 内置的写作指令。通过 `+` 添加选区、打开的稿件、导言、文献片段或诊断，已添加内容可查看和移除。单选区也可通过 `⌘K`／`Ctrl+K` 打开指令条。选区上限为 16 KiB，稿件合计上限为 32 KiB，导言和文献片段各 8 KiB。单次序列化请求上限为 48 KiB，输出上限为 32 KiB。

跨文件提议采用结构化的相对路径、原文片段和替换片段。每个原文片段必须在显式附带的文件基准内唯一匹配，重叠 hunk 会被拒绝。空文件允许一次插入。审阅支持逐 hunk、逐文件、全部接受或拒绝，以及源码跳转。源码附近同时提供待审浮层，抽屉保留完整审阅入口。

所有选定文件先完成路径、成员身份、版本、原文摘要和引用校验，再在 UI 线程写入缓冲。每个文件的多个 hunk 作为一个 Undo 操作应用。跨文件接受另提供整组撤销，只有所有目标仍处于接受后的版本且 Undo 可用时才执行。已有后续编辑、关闭、另存或跨窗口移动会阻止整组回退，单文件 Undo 历史仍保留。

app-server 运行在临时目录，使用只读沙箱和客户端审批。可执行工具被禁用，服务端工具事件和请求会被拒绝并终止该轮。提议经过审阅后才由 Nomo 修改缓冲。临时会话可连续处理多轮任务，空闲两分钟或项目关闭后结束。显式排除上下文或清空任务会重置会话，界面保留最多 8 KiB 的任务摘要，后续请求会附带这一摘要。更改模型或任务模式会建立新临时会话。

未安装、未登录或协议不匹配会显示状态和安装／更新、`codex login`、重连入口。本轮没有运行真实推理。

## 隔离试排与正文预算

### 常规项目预览

项目主文件也用于子稿件的普通预览和双栏。左侧仍编辑当前章节，PDF 区显示正在编译的主文件名。显式选择主文件、预览同项目子稿件，或检测到其他已打开稿件、已声明书目时，预览进入项目路径。当前窗口的未保存主文件、章节和书目等文本缓冲覆盖对应磁盘文件。无项目联动的独立稿件继续使用现有单文件快速路径。

项目预览在可见期间复用一份私有输入树。编辑合并后仅更新变化的缓冲文件，磁盘变化触发按元数据增量同步，移除覆盖时恢复磁盘内容。旧编译任务可取消，只有当前输入版本能发布结果。输入树沿用 512 MiB、20000 个文件上限，未保存覆盖为 16 MiB。切回源码、切离当前标签或用试排替代普通 PDF 时释放常规预览会话。项目内依赖应使用编译器可从私有树解析的路径。

诊断期间沿用每窗口的一份会话及原有页位图预算，停止段落快览进程。恢复前在编译工作协程核对磁盘输入的文件身份、大小和修改时间，以及编译器记录的外部输入，界面同时核对未保存缓冲的版本。外部输入记录上限为 4096 项和 1 MiB 路径。输入变化或依赖清单不可用时从原页重新编译。BibTeX／Biber 的依赖未包含在 TeX 记录中，使用这两个后端时重新编译。切换标签、项目或离开诊断进入其他面板会释放保留的会话。

LaTeX 使用 SyncTeX 在主稿和章节之间双向定位，生成的中间文件不会作为跳转目标。仅修改当前 LaTeX 章节且其余输入版本一致时可复用段落快览。Typst 在编译器能导出依赖清单时，仅匹配该次编译读取的项目源码，文本无法唯一定位时保留当前页或源码位置。旧版 Typst 仍可生成 PDF。 [Typst 依赖清单格式](https://github.com/typst/typst/blob/main/crates/typst-cli/src/deps.rs)

macOS 的常规项目预览仅在本次编译完全使用磁盘输入、发布前复核输入仍与镜像一致时，才按真实主文件路径更新 Finder Quick Look。Finder 仍读取最近一次成功发布的快照。带未保存覆盖的预览与待审试排均不会写入该缓存。

### 待审与编辑版本试排

试排首先冻结项目输入树，再从同一份冻结树生成编辑前和待审版本。主文件、子文件及当前窗口内其他未保存缓冲一起覆盖到临时树。试排没有真实稿件写回，也不发布正式 PDF 或 Finder Quick Look 缓存。

待审效果可在双栏 PDF 区显示，并可切换前后纸面对照。可转换的 LaTeX 片段复用段落试排路径。可靠的 PDF 文本锚点会显示定位框，无法定位时明确显示首页和定位未知状态。当前保留匹配页的两张位图及可选段落位图，工作结束即删除临时 PDF 和输入树。试排失败不会阻止有效文本提议的接受。

每次冻结最多 20000 个文件、512 MiB 输入，未保存缓冲逻辑总量为 16 MiB。为隔离写入，快照拒绝符号链接和非常规输入，使用普通副本。输出 PDF 沿用每份 128 MiB 上限。前后两份临时树仅在试排任务内存在。

页数预算可以使用 PDF 总页数，也可以启用正文范围。正文范围由用户填写“正文最后出现页”，与参考文献共页时包含该页。在 PDF 标题行打开页数设置。确认边界需要成功编译的主文件 PDF，确认值绑定该次编译、打开缓冲的版本及项目输入元数据。编辑、重新排版、关闭／移动输入或项目输入变化后会显示“正文边界待确认”。重新打开项目也需要确认。系统没有按总页数、源码比例或固定参考文献起始页推算当前正文页数。

状态栏显示正在排版、最近成功的页数或失败。排版状态的菜单可取消或重新排版，取消后可从状态栏恢复。点击失败状态打开诊断检查器，可查看最近的日志、定位源文件并返回预览重新排版。空间不足时先收起文献计数、待审计数和字数，保留排版状态及其操作。编译诊断保留源文件名和行号。XeLaTeX 启用文件行号错误格式，跳转验证项目路径后打开对应源文件。只有 `l.N` 而没有可靠文件名的日志保留原始文本。

### 已查明的框架硬限制

锁定的 MyGo 0.7.4 `ui.InputEvent` 没有公开压力或三指查询事件，无法在应用层可靠区分 Force Touch／三指查询。编辑器 `build.go` 将悬停等待写为 600 ms，`editor.State` 没有延迟配置。250 ms 悬停和上述原生手势需要上游 API 支持。当前提供固定卡、Cmd／Ctrl+Click、F12 及附件 Quick Look 等路径。

该版本的 `editor.State` 公开文本背景、行号槽标记和悬停渲染，未公开正文行布局插入区或精确行矩形。当前审阅卡锚定源码可见区，软换行和折叠下的位置需实机确认。行号槽本身沿用框架点标记，快览和审阅头通过实线／虚线字符、文字和增删符号区分语义。
