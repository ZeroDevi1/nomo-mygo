# Go Native 重写计划

把 Nomo 的界面与编辑器从 WebView（Svelte + ProseMirror + CodeMirror）迁到 MyGo 原生 UI（`github.com/egoist/mygo/ui`，Go 编写、GPU 绘制）。目的是性能：去掉常驻 WebView 进程及其内存，降低启动、输入和标签切换延迟。本文是计划，未开始实施；文中工作量均为估计，性能收益在 P0 实测前均未验证。

依据版本：MyGo v0.6.2（`go.mod`）、本仓库 `mygo-rewrite` 分支（提交 `6784fd5`）。

## 1. 目标与非目标

**目标**

- 文档窗口不再常驻 WebView。WebView 只在导出、Mermaid 等少数任务中按需创建，任务结束即销毁。
- 功能对齐当前版本（见第 5 节清单），Markdown 文件、`config.json`、`themes/<id>.json`、工作区与快照格式保持兼容，用户升级无迁移操作。
- 性能指标以 P0 实测基线为准，在同场景下全面不劣于现版本，并在稳定内存、冷启动、输入延迟三项上有可量化改善（具体门槛在 P0 结束时定稿）。

**非目标**

- 不改变 Markdown-first：`.md` 原文始终是唯一保存格式。
- 不重写 Quick Look 扩展：它仍用 `src/quicklook` 的 Web 渲染器，只读取同一份配置。
- 不在本计划内新增产品功能；迁移期间发现的行为差异按“保持现状”处理，确需调整的单独评审。

## 2. 现状与可复用能力

### 2.1 现有前端规模

| 范围 | 行数（TS/Svelte/CSS，不含测试） |
|---|---:|
| `src/lib/editor-core`（ProseMirror 核心、NodeView、插件） | ~25,000 |
| `src/lib` 其余（排版、渲染服务、分段编辑、大纲、主题等） | ~12,400 |
| `src/app`（外壳组件、服务、样式） | ~53,000 |
| 合计 | ~90,000 |

Go 侧 `desktop/`（文件、分段文档引擎 `textdoc`、配置、窗口生命周期、外部打开、标签移交、导出、图片资源、更新）已在本分支完成，原生化后可直接调用，不再经过 IPC 绑定。

### 2.2 MyGo 原生 UI 能力对照

| 能力 | MyGo 提供 | 对 Nomo 的可用度 |
|---|---|---|
| 窗口、自绘标题栏、vibrancy | `ui` + `TitleBarHidden`、`c.TitleBar()` | 直接用 |
| 标签、侧栏、树、分栏、工具栏、菜单、弹层、对话框、Toast、Tooltip | `ui` 组件库 | 直接用，按设计稿定制外观 |
| 代码编辑器（多光标、折叠、查找替换、只绘可见行） | `ui/editor` | 源码模式、TXT/JSON 分段编辑可用；内置 28 种语言高亮，少于 Shiki |
| 大文本缓冲 | `ui.TextBuffer`（rope、UTF-16/行索引、快照 O(1)） | 作为文档唯一事实源 |
| 自定义输入客户端 | `TextInputClient`（输入法组字、原生文本查询、无障碍） | 自研编辑器的输入基础 |
| 文字整形与绘制 | `ui.Shape`、`Painter.Glyphs`、`Font.Metrics` | 自研段落布局与 KP 排版的基础 |
| Markdown 解析 | `ui/markdown/parser`（GFM、脚注、数学；块带源码 `Start/End`；增量重解析） | 可作解析基础，需扩展 callout、front matter、HTML 块细节与八类行内语法 |
| Markdown 只读视图 | `ui/markdown` | 小窗/预览可参考；数学只显示 TeX 原文 |
| 富文本编辑器 | `ui/richtext` | **不采用**：扁平段落模型，表格存成制表符段落，导出丢对齐，无法保证源码保真 |
| SVG | `ui.ParseSVG` | 支持路径与基本形状；**不支持 text**，Mermaid 输出不能直接显示 |
| PDF | `Page.PrintToPDF` | 依赖 WebView 页面 |
| 嵌入 WebView | `ui.WebView` / `Window.NewWebView` | 用于按需渲染服务 |

结论：外壳与源码编辑可直接组合现有组件；语义编辑器必须自研；Mermaid、PDF/Word 导出短期内保留 Web 实现，以按需 WebView 运行。

## 3. 核心架构决策

### D1 Markdown 原文是唯一事实源

文档状态 = `ui.TextBuffer` 中的 Markdown 原文 + 增量块索引。语义视图是原文的**投影**：光标或选区所在的行内格式就地展开原文（沿用现有“八类行内显隐”的交互），其余部分按渲染结果显示。

- 不再有 ProseMirror 文档 ↔ Markdown 的序列化往返，保真由构造保证，现有的表格反斜杠、HTML 规范化等首次编辑差异问题随之消失。
- 源码模式、语义模式、双栏共享同一 buffer 与同一撤销历史；双栏同步按源码偏移映射，替代 `scrollSyncMapping.ts` 的节点映射。
- 语义命令（加粗、列表切换、表格增删列等）全部实现为对原文的区间替换事务。
- 代价：表格、嵌套列表、callout 等结构在投影中编辑时，需要把结构操作翻译成原文编辑，交互复杂度集中在这里（见风险 R2）。

### D2 自研语义编辑器组件 `desktop/ui/mdedit`

- 输入：`TextInputClient` 接 buffer；输入法组字作为虚拟插入，提交后与被替换内容合为一步撤销。
- 布局：块级布局结果按块缓存，只布局可见区附近，其余块用估算高度；缓存以估算字节计上限并 LRU 淘汰，标签转入后台时释放布局、保留 buffer。
- 排版：`src/lib/typography`（KP 断行、中文规则、Liang 断词，约 2,600 行纯算法）移植为 Go 包，基于 `ui.Shape` 取字形宽度；行内对象（公式、图片、代码）作为不可拆分盒子参与断行。
- 绘制：`Painter.Glyphs` + 自绘选区背景（连续行矩形合并，对应 `selectionPaint.ts`）。
- 解析：基于 `ui/markdown/parser` 扩展（或 fork 到本仓库），补齐 callout、front matter、Nomo 的八类行内语法、HTML 锚点；解析结果只描述区间，不复制正文。

### D3 增强渲染分级

| 内容 | 方案 | 说明 |
|---|---|---|
| 代码高亮 | `ui/editor` 的 Tokenizer | 内置语言不覆盖时显示为纯文本；常用缺失语言按需补 Tokenizer |
| 公式 | P0 二选一：① 嵌入 JS 引擎运行 MathJax 输出纯路径 SVG，交给 `ui.ParseSVG`；② 按需 WebView 用 KaTeX 渲染后取位图 | ① 引入新依赖，需确认；② 无新依赖但首个公式有 WebView 冷启动成本。结果按“源码哈希 + 字号 + 主题”缓存，有字节上限 |
| Mermaid | 按需 WebView 渲染，输出位图（或文字转路径的 SVG） | Mermaid 依赖 DOM 测量文字，不适合纯 JS 引擎 |
| HTML/PDF/Word 导出 | 按需 WebView 复用现有 `src/app/services/export`、`word/` 管线 | 导出入口改为把 Markdown 快照与主题交给离屏页面 |

渲染服务统一约束：单实例 WebView 按需创建，空闲超时（初定 30 s）后 `Destroy`；有界并发队列，任务可取消，标签切走或文档修订变化即作废结果。这样“有 Mermaid 的文档”才付出 WebView 成本，普通文档不付。

### D4 后端直接调用

`desktop/` 现有命令从 IPC 绑定方法改为 Go 包内调用；`bridge.go`、`bindings.gen.ts`、`src/lib/desktop/runtime` 随前端一并移除。`textdoc`、`docfs`、`config`、`applog`、`i18n` 保持不动。

### D5 主题与本地化

- `themeRegistry.ts` 的颜色/样式令牌转为 Go 结构，用户主题 JSON 格式不变，校验规则对齐 `userThemeDefinition.ts`。
- 界面文案从 `project.inlang/messages/*.json` 生成 Go 侧访问代码（沿用 inlang 作为唯一来源），Quick Look 仍用 paraglide。

### D6 生命周期

遵循 `AGENTS.md`：文档状态（buffer、撤销历史、阅读锚点）与视图（布局缓存、渲染结果、输入客户端）分离；后台标签只保留前者。所有 goroutine、定时器、WebView 都有明确的取消与释放路径。

## 4. 分阶段计划

工作量为单人估计，供排期参考，不作承诺；每阶段结束有门禁，未达标不进入下一阶段。

### P0 基线与可行性原型（3–4 周）

1. 按 `AGENTS.md`“性能验证基准”测量现版本：空白文档、纯文本、四标签、代码/图表/图片较多的文档，Release 构建、固定窗口尺寸与 DPI，每项三轮；记录私有驻留、私有提交、JS 堆、GPU，冷启动、输入延迟、标签/模式切换延迟。
2. 原型 `mdedit`：段落、标题、行内强调与链接的投影/原文展开、中文输入法、选区、撤销重做，打开 `sample.md` 与 10 万字文档。
3. 原型 KP 排版移植一段，验证 `ui.Shape` 精度与性能足够。
4. 公式方案 ①/② 各做一次实测。

**门禁（Go / No-Go）**：原型在 10 万字文档中单次按键到上屏 p95 ≤ 16 ms；中文输入法（macOS 拼音、Windows 微软拼音）组字、候选窗位置、撤销正确；同等内容下稳定内存明显低于基线。任一不满足则停止全量重写，回退到“只原生化设置窗口”的方案。

### P1 设置窗口原生化（2–3 周，可独立发布）

设置窗口已是独立小窗口，与编辑器无耦合，原生化后直接少一个 WebView。覆盖主题/字体/排版/更新/文件关联/图片配置全部页签，读写同一 `config.json`。这一步同时沉淀原生组件样式、主题令牌 Go 化和 i18n 生成，为后续阶段铺路。

### P2 原生外壳与编辑器 MVP（10–14 周，不发布）

在独立入口（构建标签或启动参数）中开发，现版本照常发布。

- 外壳：标题栏与菜单、标签、资源管理器、状态栏、工具栏、空白页与最近打开、确认/外部变更/未保存对话框。
- 编辑器：段落、标题、列表（含嵌套）、任务、引用、代码块、分割线、链接、图片、表格；源码模式（`ui/editor`）与模式切换；搜索替换；大纲与跳转；剪贴板（Markdown、HTML、图片粘贴落盘）；保存、自动保存、恢复草稿、外部变更。

**门禁**：用现有回归语料（`README.md`、`sample.md`、`src/lib/editor-core` 测试中的 Markdown 用例）做“打开 → 不编辑 → 保存”字节级不变；基础编辑命令行为与现版本一致。

### P3 增强内容（8–10 周）

KP 排版全量、公式、Mermaid、callout、脚注、HTML 块与锚点、注释块、TOC、emoji 补全与选择器、快捷插入菜单、行内代码高亮、标题层级角标、整段选择、三击选块、链接快速编辑。

### P4 工作区能力（6–8 周）

多窗口、组合标签与双栏对照、标签跨窗口移交与屏幕拖动、大纲拖拽重排、阅读位置、文档小窗（置顶/只读降级/过渡）、TXT/JSON 分段编辑（`ui/editor` + `textdoc`）、写作统计、Markdown 格式检查。

### P5 导出、切换与清理（4–6 周）

- 导出 HTML/PDF/Word 改走按需 WebView 渲染服务。
- 灰度：原生版作为可选开关随正式版发布一个版本周期，收集问题；默认切换后再保留一个版本的回退开关。
- 清理：移除 Svelte 应用、ProseMirror/CodeMirror 依赖、IPC 绑定；`vite` 只保留 Quick Look 渲染器与导出离屏页面的构建。
- 更新 `CLASSMAP.md`、`CONTEXT.md` 与构建/发布脚本。

**合计约 33–45 周（单人）**，不含设计稿与测试人力。

## 6. 性能预算与验收

- 每阶段结束按第 4 节 P0 的同一流程复测，与基线对照；切换与打开关闭各 20 轮，区分预热缓存与持续增长。
- 热路径约束：单次按键只重解析受影响块、只重排受影响段落；滚动不触发全文布局；后台标签不绘制、不排版。
- 缓存一律给出容量、估算字节与淘汰策略：块布局缓存、字形缓存、公式/图表结果缓存、图片解码缓存。
- 报告区分私有驻留、私有提交、Go 堆、GPU 资源，不简单相加；`MYGO_FRAME_STATS` 用于定位超过 8 ms 的帧。

## 7. 风险与缓解

| 编号 | 风险 | 缓解 |
|---|---|---|
| R1 | 自研编辑器的输入法、选区、无障碍边界情况多，Windows（TSF）尤甚 | P0 门禁先验输入法；每阶段在 macOS/Windows 实机回归 |
| R2 | 投影编辑下表格、嵌套列表、callout 的结构操作复杂 | 结构命令统一为原文事务，配套字节级保真回归；复杂块允许“块内临时展开原文”退路 |
| R3 | 公式/Mermaid 渲染仍需 WebView 或 JS 引擎 | 只在出现时按需创建并空闲销毁；结果缓存；首帧先显示原文占位 |
| R4 | 重写周期长，期间新功能需双份实现 | P2 起冻结非紧急新功能，或仅在原生版实现并延后上线 |
| R5 | MyGo 原生 UI 仍在快速演进（v0.x），API 可能变化 | 锁定版本；自研组件只依赖 `TextInputClient`、`Shape`、`Painter` 等底层接口 |
| R6 | 代码高亮语言覆盖少于 Shiki | 统计用户常见语言后按需补 Tokenizer；其余显示为纯文本 |
| R7 | 性能收益不及预期 | P0 门禁与每阶段复测；不达标时止损，保留 P1 成果 |

## 8. 待决策事项

1. 公式方案选 ①（引入 JS 引擎依赖）还是 ②（按需 WebView），P0 实测后定。
2. 是否接受 P2–P4 期间冻结非紧急新功能。
3. Linux 是否要求完全不依赖 WebKitGTK：若要求，导出与 Mermaid 需另寻纯 Go 方案，工作量显著增加。
4. 原生版是否继续支持 macOS 12（现 `minimumSystemVersion`）。

## 9. P0 进展（2026-10-22）

### 9.1 已完成：`mdedit` 原型（P0 第 2 项）

代码在 `desktop/ui/mdedit`。原型最初的独立入口 `desktop/cmd/mdedit-proto` 已由 9.7 的原生外壳取代并删除。

- 原文为唯一事实源；`parser.Document.Edit` 增量重解析，顶层块索引按前后缀匹配增量维护（随机 400 次编辑与全量解析逐块一致）。
- 段落与标题按行内语法投影：光标触及的强调、链接、行内代码标记就地展开，标题前缀与转义符在光标位于本块时显示；其余块原样显示（R2 退路）。
- 可见区虚拟化：只布局可见片段；原样块（代码块等）按源码行布局，编辑时按行哈希复用未变行；块级阅读锚点，估算高度被实测替换时不跳动；布局缓存按估算字节 LRU 淘汰（默认 8 MB），`ReleaseLayouts` 供后台标签释放。
- 输入：`TextInputClient` 以原文 UTF-16 坐标对接输入法；组字为虚拟插入，提交后与被替换内容合为一步撤销；连续键入、连续删除合并；撤销栈不裁剪。
- 打开 → 不编辑 → 原文字节不变（`sample.md`、`README.md`）。

### 9.2 实测（无头 CPU 渲染，未经真机验证）

环境：Apple Silicon、macOS、Go 1.27.1、MyGo v0.6.2，`ui.Tester` 1200×900，按键 → 编辑 → 重建并绘制一帧。无头渲染在 CPU 上光栅化，比 GPU 窗口更保守，但不含合成与上屏延迟。

| 场景（10.3 万字符、788 块） | p50 | p95 |
|---|---:|---:|
| 键入 ASCII | 1.2 ms | 1.7 ms |
| 键入中文 | 1.6 ms | 2.2 ms |
| 拼音组字/提交 | 1.8 ms | 2.4 ms |
| 退格 | 1.9 ms | 2.4 ms |
| 方向键 | 0.5 ms | 2.0 ms |
| 滚动 120 DIP | 1.2 ms | 3.3 ms |
| 3000 行代码块内键入 | 1.3 ms | 1.6 ms |
| 2 万字无换行单段落内键入 | 10.5 ms | 10.8 ms |

打开 10 万字文档到首帧约 50 ms；测试进程 Go 堆 15 MB（含无头渲染宿主），布局缓存约 5 MB。真机窗口首帧 870 ms，其中 808 ms 为 MyGo 首次编译 GPU 管线（`present`），属框架冷启动成本，需计入冷启动基线。

### 9.3 与计划的偏差

- **未用 `ui.TextBuffer` 作事实源**：`parser.Document` 必须持有完整原文，再维护一份 rope 会让正文常驻两份；解析器使用字节偏移，而 `TextBuffer` 没有字节与 UTF-16 的换算。原型以解析器原文为唯一副本，块级前缀和提供 UTF-16 换算，撤销记录差量文本而非快照。
- **行高**：`ui.TextLayout` 不能设置行高，正文按字体自然行高排列，与现版本约 1.75 倍行高不一致；需在 KP 排版移植（第 3 项）中基于 `Shape` + `Painter.Glyphs` 自研行布局解决。

代码在 `desktop/ui/mdedit/images.go`（缓存与加载）、`imageview.go`（排版与绘制），外壳每个窗口一个缓存（`shell.go`），按标签设置文档目录（`appearance.go`）。

- 显示：Markdown 图片与行内 `<img>` 在投影中替换为占位字符，排版为 MyGo 行内对象（`Span.ObjectWidth/Height`），与原版一样和文字同行排列；尺寸按原版规则（`width` 为像素或相对行宽的百分比，否则原始尺寸，宽度不超过行宽）。只含图片的 HTML 块（原版设置宽度后的 `<img>`、README 的 `<p align="center"><img></p>`，允许 `a`/`p`/`div`/`center`/`span`/`br` 包裹）整块显示为一行图片，`align` 生效。
- 编辑：光标严格位于图片原文内时展开为原文；方向键经过、点击图片旁边仍显示图片（避免大图反复变成原文造成版面跳动）；点击图片本身把光标放进其原文。
- 加载：本地路径（相对文档目录、`file://`、百分号编码）、data URI 与 http(s)；本地与远程各一条队列、各至多 2 个 worker，远程慢时不阻塞本地；远程 20 秒超时、不带 Referer、40 MB 上限。PNG/JPEG/GIF（首帧）/WebP/BMP/SVG；超过 2400 像素边长或 4 M 像素的位图解码后缩小（双线性）再保留，按 EXIF 方向摆正。加载中显示占位底色，失败显示带图标的替代文字框，5 秒后再次请求时重试。窗口获得焦点时后台校验已加载本地图片的修改时间，变化的重新加载。
- 缓存：窗口内各标签共用，字节预算 64 MB（宽 × 高 × 4 × 4/3，含缩小绘制时的 mipmap；GPU 纹理另计），按最近使用淘汰本帧未绘制的图片；另记住原始尺寸（至多 4096 项，约 400 KB），淘汰后重新加载期间按真实尺寸占位，行高不变。加载完成只让含图片的行重新计算尺寸，尺寸未变不重排。新增常驻：每窗口一个缓存结构；无图片的文档没有 worker 与额外内存。

实测（无头 CPU 渲染）：10 万字文档（无图片）键入中文 p95 2.0 ms、滚动 4.5 ms，与 9.10 持平；30 张 1200×800 本地图片的文档（解码后约 150 MB，超出预算）连续滚动，缓存峰值 63.5 MB，往返滚动总高度稳定，滚动帧 p50 6.9 ms、p95 12.7 ms、最大 38 ms（CPU 光栅化缩放大图，GPU 窗口需实机复测）。截图核对：README（居中图标块、GIF 首帧、远程徽章）、行内图标、百分比宽度、缺失图片、列表内图片。

已知差异与未做：远程 SVG 徽章只显示色块，文字不显示（MyGo SVG 渲染不支持 `<text>`）；GIF 不播放动画；图片右键菜单、拖动调整宽度、图片对齐设置、点击预览未实现；含图片的列表项，项目符号按首行顶部对齐而非基线；一般 HTML 块（如 `<h1 align>`）仍按原文显示。真机窗口未验证。

### 9.13 测试集跑测与缺失功能补齐（2026-10-23）

用“Nomo 性能测试集 2026-10-22”（434 个文件、131 MB）逐文件检查原生语义编辑器与外壳。跑测工具：`desktop/ui/mdedit/corpus_test.go`（`NOMO_CORPUS=<目录>`，逐文件：编码往返、打开后原文不变、首帧、滚动到 25/50/75/100%、查找 `NOMO_END` 并跳转、键入中文再撤销、Go 堆与缓存；`NOMO_CORPUS_OUT` 输出报告与首屏截图）与 `desktop/ui/shell/corpus_test.go`（编码/换行样本经外壳“打开→保存”与“输入撤销→保存”字节不变、四标签切换 20 轮、打开—编辑—关闭 20 轮、256 文件目录树展开与打开）。无头 CPU 渲染，不代表 GPU 窗口与进程内存。

**修复的缺陷**
- 纯 CR 换行文件打开即崩溃（块区间延伸到下一个 LF 时重叠）：块索引保证区间不重叠；外壳打开时把 CRLF/CR 统一为 LF 编辑，保存时还原原换行风格，混用换行且未编辑时原样写回（`tab.go`）。
- 超长单行（6 万字节 JSON 行、64 KiB 不可断字符串、1 MiB 单段落）首帧 0.5–1.6 s、且行内每次按键整行重排：排版耗时随长度超线性（4 KB 1.5 ms、64 KB 200 ms），超过 4 KB 的原文行分段排版，超过 16 KB 的段落按原样行显示；三者首帧降到 39–54 ms，长行内键入远低于 60 ms。
- 超宽表格（64 列）超出窗口无法查看：移植原版列宽策略（`widths.ts`：表头、正文 p90、最长值、em 上限），放不下时整表横向滚动（横向滚轮或 Shift+滚轮，光标进入屏外单元格时自动滚动，底部滚动条）；与原版的差异：整表已需滚动时按首选宽度排，避免短值折行。
- 离屏渲染开发中发现并修复：UI 线程与渲染 worker 争用同一把锁的死锁、隐藏窗口里 `requestAnimationFrame` 被暂停导致渲染不返回（改用定时器、JS 与 Go 两侧都加超时）、渲染与本地图片共用队列被拖住（渲染单独一条串行队列）。

**补齐的功能**
- HTML 块静态预览（原版 tableHtml 插件）：白名单同原版 `sanitizeHtml`，段落、标题、列表、引用、pre、合并单元格表格、图片与行内格式按排版结果显示，光标进入块内显示原文；含白名单外标签（`details`、`script` 等）的块与原版一样按原文显示。HTML 注释块显示为“注释”卡片。
- 目录卡片：`<!-- toc -->…<!-- /toc -->` 合并为一个合成块，按当前标题实时生成（序号、按级缩进），只排版可见条目，点击跳到标题；与原版的差异：目录区的 Markdown 列表原文不随标题自动更新（原版 tocSync 会改写原文；原生版的撤销栈按绝对偏移记录，无历史的自动改写会破坏撤销）。
- 脚注引用显示为标签（小号链接色），点击跳到定义。
- GIF 动画：解码全部帧（按处置方式合成），按时间选帧，只在可见时预约下一帧；全部帧超过 32 MB 时退回首帧。
- 公式（行内 `$…$`、`$$…$$`、公式块）与 Mermaid 代码块（计划 D3 方案 ②）：前端新增离屏页面 `render.html`（KaTeX 与 mermaid，调用与原版相同），外壳在需要时创建隐藏窗口，逐个渲染、缩窗截图并裁剪为位图，空闲 30 秒后销毁窗口；结果进入图片缓存（字节预算、淘汰、加载后重排），主题变化后重新渲染；行内公式按基线深度与正文对齐；错误公式按原版显示红色原文，无效 Mermaid 显示源码首行，均不影响后续内容。

**测试集结果**（全部 81 个主样本与 256 个目录树文件：保真、打开不变、键入撤销均无问题）
- 首帧：普通样本 2–65 ms；50 MiB 纯文本 126 ms；1 万行表格 64 ms。
- 外壳：编码样本 9 个全部字节不变；四标签切换 80 次 p50 2.6 ms，Go 堆 19.6→23.5 MB；打开—编辑—关闭 20 轮堆 9.2→9.5 MB；目录树全部展开并绘制 27 ms，打开文件 p50 13 ms。
- 真机（macOS，release 构建，隔离 HOME）：目录卡片、行内公式、公式块（aligned）、七类 Mermaid（流程/时序/类/状态/饼图等）、无效公式与无效 Mermaid 的错误隔离均正确；800 公式文档跳转后一屏约 10 个公式 3 秒内渲染完成（单个 200–300 ms，缓存命中即时）；离屏 WebView 内容进程（约 73 MB）空闲后释放。

**仍超出预算或未做**
- 大文件按键延迟随体量线性增长（10 MiB 混合 20 ms、50 MiB 36 ms）：主要是 MyGo 解析器 `parser.Document.edit` 每次编辑复制整篇原文并平移全部块偏移，以及随之而来的 GC；属于上游实现，需上游提供增量原文存储。
- 超宽表格内键入约 19 ms：整张表是一个顶层块，表内每次编辑重建全部单元格行（7680 个）；需改为表格内按行增量重建。
- 公式渲染逐个截图（单个 200–300 ms），可改为一次渲染多个、一次截图后分别裁剪。
- 导出 HTML/PDF 中公式与 Mermaid 仍以源码显示；源码模式没有表情建议、公式与图表预览。
- 计划 P4/P5 的工作区功能尚未开始：双栏对照与组合标签（测试集“组合对照”样本）、多窗口与标签移交、文档小窗、托盘、TXT/JSON 分段编辑、Word 导出；正文行高仍待上游支持。

### 9.15 绕开上游限制（2026-10-23，不修改 MyGo）

- **正文行高**（`mdedit/lines.go`）：MyGo v0.6.2 的 `TextLayout` 无行高参数。保留原排版，按视觉行（取自整段选区矩形）计算每行下移量，使行框至少为字号 × 行高（多出部分上下各半，同 CSS）；光标、命中测试、选区、行内对象全部按行换算，绘制时逐个可见行裁剪到原行框后平移（Painter 对裁剪区外的行只做一次比较即跳过）。规则同原版样式：正文、列表、引用、表格单元格用设置 `lineHeight`（默认 1.75，设置页恢复 1.4–2.1 滑块），标题 1.2，代码/公式/HTML 保持原生行高。整行选区覆盖行距、相邻行连成一片。成本：每个视觉行 16 字节，排版时多一次选区矩形遍历。已知限制：超出原行框的字形墨迹会被裁掉（常见字体无此情况）。实机验证：行距、列表符号与任务框对齐、多行选区连续、代码块不受影响。
- **大文档按键延迟**：
  - 剖析（10 MiB 混合）：上游 `parser.edit` 40%，我们自己的 `Document.collect`（每键遍历全部顶层子块）30%，GC 18%；50 MiB 纯文本中 `collect` 占 54%。
  - `Document.recollect`：编辑后只收集受影响的顶层块——保留编辑点之前的块（退一块以覆盖懒惰续行/Setext/列表续行），找第一个在新解析中按序号差与偏移差对齐的旧块作为后缀并就地平移，中间段从解析器重新收集；涉及 front matter、目录区或无法对齐时退回全量收集。
  - 分段解析（`mdedit/chunks.go`）：≥ 2 MiB 且不含链接引用/脚注定义的文档，在“前一段以空行结束且末块不会延续（未闭合围栏/HTML/公式块）、后一段首行第 0 列且非列表标记或缩进”的位置切成约 256 KiB 的段，各用一个解析器，全局序号与偏移按段换算；编辑破坏切分条件时与相邻段合并，段过长（如围栏闭合后）且末尾闭合时重新切分，编辑中出现定义时合并为一段。随机编辑对照测试逐块、逐行内节点与整篇解析一致。
  - 结果（无头，`TestTypingLatency`，文档中部连续键入 60 字，每键含一帧）：

    | 文档 | 改前 p50 / max | 增量收集后 | 分段后 |
    |---|---|---|---|
    | 10 MiB 混合 | 14.2 / 28.4 ms | 8.6 / 17.7 ms | 1.1 / 4.6 ms |
    | 50 MiB 纯文本 | 25.4 / 38.8 ms | 10.1 / 20.2 ms | 3.6 / 9.1 ms |

    5 MiB 混合 0.77 ms、20 MiB 纯文本 1.8 ms。剩余主要是整篇原文拼接（O(n) 内存复制）、GC 与绘制。
  - 代价：分段文档的各段解析器持有自己的段文本，原文多占一份。解析后堆增量 10 MiB 混合 106 → 121 MB、50 MiB 纯文本 131 → 186 MB；解析耗时 83 → 92 ms、95 → 112 ms；小于 2 MiB 或含定义的文档不变（与原文共享字符串）。
  - 测试集全量回归（339 个文件）：保真、打开不变、键入撤销均无问题。
- **SVG 文字**：MyGo SVG 渲染不画 `<text>`（远程徽章只剩色块）。含 `<text>` 的 SVG 在加载线程经离屏渲染页以 `<img>` 栅格化（不内联，脚本与外部资源不执行），失败时退回矢量显示。实机验证本地徽章文字正确。限制：位图按设备像素比生成，放大显示会模糊；透明圆角处为浅色主题背景。

### 9.16 按测试集流程跑测与对照原版补齐（2026-10-23）

- **流程自动化**：外壳测试集新增 `protocol` 场景（`desktop/ui/shell/corpus_test.go`）：01–08 每个样本 3 轮，经外壳打开到首帧，依次切换源码、双栏、语义（原文不变），在测试集临时副本中另存同目录副本后重新打开（原文一致、相对图片路径可解析）。
- **跑测发现并修复**：
  - 状态栏写作统计每个原文版本整篇重算（10 MiB 约 0.84 s）：改为按编辑增量维护（只重算编辑点两侧到最近“词边界重置字符”之间的区间），首次整篇统计加 ASCII 快速路径（10 MiB 35–39 ms）。切换到源码模式 10 MiB 混合 1.5 s → 约 0.09 s，50 MiB 6 s → 0.19–0.23 s（外壳测试集 protocol 场景 3 轮）。
  - 大纲面板每帧为全部标题建元素：改为虚拟列表。外壳层每键 10 MiB 混合 8.6 → 2.6 ms。
  - 已知未改：`04_代码长行与嵌套围栏.md` 首次进入源码模式约 0.36 s，来自 MyGo 源码编辑器对超长 JSON 行的首次语法高亮（上游）。
- **逐样本键入延迟**：77 个主体样本各在中部连续键入 60 字，p50 中位数 0.33 ms。巨大单块是瓶颈：万行表格 50 ms、25000 行代码块 15.8 ms，原因是块内每次编辑都重新展开整块（12 万个单元格行或 2.5 万行）并在 IME 接口中从块首数 UTF-16。改为单行修补（`patch.go`：编辑落在一个单元格或一行内且解析结果显示结构未变时只平移后续行区间）与大块 UTF-16 检查点（每 4 KB 一个，按版本缓存），块内编辑的块 UTF-16 长度按差值更新。修复后万行表格 12.9 ms（其中约 10.7 ms 为上游解析器重解析整张表）、25000 行代码块 2.1 ms、2000 行表格 2.8 ms；400 节点单图编辑源码时整块作为一行排版，约 11 ms，未改。
- **折叠块（原版 1aa9342）**：`<details>`/`<summary>`/`</details>` 顶层标记配对为框架；正文按层级缩进、卡片边框逐块绘制（12 层嵌套正确）；标题行三角切换临时展开（不写原文、不进撤销），`open` 为默认状态；折叠正文高度为 0，方向键越过，查找/大纲跳转/撤销进入折叠区时自动展开；插入（工具栏、菜单、快捷插入、右键、源码模式模板）、默认展开与取消折叠（标题行右键）；导出 PDF 展开全部折叠块，导出样式加入卡片边框。未配对标记（如缺少 `</details>`）按原文显示；列表、引用中的折叠块按原文显示。标记解析按块原文缓存、不涉及标记块的编辑就地平移索引，含 4224 个标记块的 10 MiB 文档每键约 1.4 ms。
- **编辑区右键菜单（原版 buildEditorContextMenuItems）**：选区（编辑项、格式子菜单、链接）、折叠块标题、链接（打开、复制地址）、标题（级别、段落）与普通文本（撤销重做、编辑项、插入子菜单）。代码块、表格、公式与图表的专属菜单按普通文本处理。

### 9.19 Windows 进程清理、大文档传输与内存归还（2026-10-23）

- **关闭后进程残留**：WebView 外壳注册了空的 `OnWindowAllClosed`，在“关闭窗口”行为下关掉最后一个文档窗口后，进程与托盘一直留在后台（MyGo 只在包括隐藏窗口在内的全部窗口关闭后才触发该事件，隐藏的设置窗口、PDF 导出窗口也会挡住它）。改为 Windows/Linux 上最后一个文档窗口销毁后走统一退出事务（`exitAfterLastDocumentWindow`），事务失败时直接退出；“关闭到托盘”只隐藏窗口不受影响；macOS 保持驻留。原生外壳：隐藏的公式/图表渲染窗口在外壳关闭后不再被排队请求重建（`renderService.closed`），否则进程要等 30 秒空闲计时器。
- **托盘图标残留**：MyGo 的 `App.Exit` 与 `Quit` 都不删除通知区域图标，Windows 上进程结束后图标留到鼠标经过才消失。退出事务、更新安装器退出与原生外壳 `OnWillQuit` 前先 `destroyAppTray`。
- **WebView2 参数**：MyGo 不传附加浏览器参数；按 Tauri（wry）的 Windows 默认补上 `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection`（关掉 SmartScreen 网址检查及其常驻进程、选中文字迷你菜单、PDF 界面），软件渲染时追加 GPU 参数；启动前已有同名环境变量时原样保留。
- **大文档正文传输**：MyGo 把调用结果拼成 `__mygo.receive([...])` 经 `ExecuteScript` 投递，macOS 的 JavaScriptCore 按 JSON 快速解析，WebView2（V8）要整段转 UTF-16 并编译。`read_markdown_file` 超过 1 MiB 的正文改为暂存（一次性令牌、一分钟有效），页面经 `nomodoc` 协议 fetch。macOS 实测（WebView 外壳、10 MiB 混合、release、隔离 HOME）：页面计时 `read_markdown_file` 23 ms，打开到读取完成的日志 18.5 s（旧路径 21.6 s），两者都主要花在编辑器载入文档，WebContent 进程约 6.2 GB；Windows 上的收益未实测。
- **关闭大文档后归还内存**：Go 后台回收器归还空闲页很慢，关闭 50 MiB 文档后约 299 MB 空闲堆仍计入进程提交内存。关闭 ≥ 4 MiB 的标签、释放分段会话后合并请求，2 秒后执行一次 `debug.FreeOSMemory`（`internal/memtrim`）；无头实测 2.5 秒后空闲未归还堆 299 MB → 0。
- 验证：Go 全部测试、`GOOS=windows go vet ./...`、`pnpm check`、前端相关 vitest；上述 Windows 行为（退出、托盘、WebView2 参数）只做了交叉编译与静态检查，未在 Windows 实机验证。
- 发现未改：WebView 外壳打开 10 MiB 混合文档时 WebContent 进程约 6.2 GB、载入约 18 秒（前端编辑器）；WebView 外壳收到 SIGTERM 后未退出（退出事务等待页面确认）。

### 9.20 原生外壳设为默认界面（2026-10-23）

- **选择顺序**（`nativeShellRequested`）：命令行 `--webview` / `--native`（临时，不写设置）→ 环境变量 `NOMO_SHELL=webview|native`（兼容 `NOMO_NATIVE=1|0`）→ 设置 `desktopShell`（两种外壳的“高级 → 渲染”都可切换，重启后生效）→ 默认原生。启动日志记录所选界面。实机验证（release、隔离 HOME）：默认 → 原生；`--webview` → WebView；设置为 WebView → WebView；设置为 WebView 时 `--native` → 原生。
- WebView 外壳与其前端保留为回退，打包内容不变。

**原生版相对 WebView 版仍缺少的功能**（按影响排序；“未验证”指已实现但未在真机窗口操作过）
